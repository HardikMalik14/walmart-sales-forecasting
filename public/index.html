Inputs, assumptions & boundaries

    Behind Sales Pred Engine

    An honest separation between the saved research benchmark and live experiments.

    ORIGINAL REPOSITORY
    01 / THE SAVED STUDY

    Four models. One historical window.

    The original pipeline uses Walmart’s 45-store dataset from 2010–2012. It holds out the final 29 weeks chronologically and compares Seasonal Naive, SARIMA, Prophet and XGBoost at chain level.

    Benchmark controls recalculate errors from the saved predictions; they do not change the original split or refit the models. XGBoost learns globally across stores and forecasts recursively, feeding earlier predictions into later lags.

    02 / THE LIVE LAB

    Real fitting, within web limits.

    The lab reuses the repository’s Seasonal Naive and XGBoost wrappers. It scores a chronological holdout first, then fits on all available history for future forecasts.

    The web XGBoost probe is capped at 300 trees with an 8-week inner validation window and one CPU thread. The original wrapper determines the final refit tree count. SARIMA and Prophet training remain in the original CLI, outside this bounded web lab.

    03 / HISTORY STAYS IN THE PAST

    Lags never read future actual sales.

    Lag and rolling features use earlier rows within the same store. During recursive forecasting, predicted values—not observed future sales—feed subsequent steps. The seasonal baseline repeats sales from 52 weeks earlier.

    Holdout temperature and holiday flags are treated as known. For future weeks, temperature is held at each store’s last observation plus the selected adjustment. US holiday flags follow the original calendar. These are explicit input assumptions.

    04 / WHAT THIS DOES NOT PROVE

    One good window is not a guarantee.

    The archived test window has no Q4 holiday peak. The original README documents that test data helped identify a feature issue, with the chosen fix subsequently checked on a training-only inner fold.

    Live synthetic data is generated, not Walmart’s actual business data. The original saved predictions are historical observations and model outputs. Future forecasts have no measured future accuracy, and the site does not invent confidence bands.

    Original archived model settings

    These belong to the saved benchmark. Live-lab settings are reported separately in its downloaded JSON.

    Using your own data

    Required columns are Date and Weekly_Sales. Dates must be consecutive weekly Fridays in YYYY-MM-DD or DD-MM-YYYY format. Each store must have identical weeks. Store IDs must be positive integers. Missing temperature defaults to 60°F, missing holiday flags use the original calendar, and missing Store means one aggregate series. Those assumptions are listed after processing.
